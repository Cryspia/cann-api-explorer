# Ascend C · DetermineSync (deterministic-compute sync, ⚠️ simulation deadlock / not made into a unit)
- Category: sync/　- API: `InitDetermineComputeWorkspace` / `WaitPreBlock` / `NotifyNextBlock`　- include: `kernel_operator.h`
- Purpose: ensure multiple cores execute a section in blockIdx order to obtain a deterministic result.
- **Observed problem**: this chained implementation (core i `WaitPreBlock` waits for its predecessor -> writes chain -> `NotifyNextBlock`, with an `if` to skip for core 0 / the last core) **deadlocks** under CAModel multi-core simulation: sim_exe runs at 607% CPU, does not exit after 34 minutes, and consumes 7GB+ of memory. The suspected root cause is that `if(idx>0)/if(idx<num-1)` breaks the strict pairing of Wait/Notify, so some core waits forever in `WaitPreBlock` for a notification that never arrives; this API may require **every core to call Wait+Notify in pairs** (self-consistent by idx internally) and cannot be trimmed at the chain head/tail.
- Already removed from the count (meta.json.unsupported); the code is retained as a counter-example reference. **The multi-core sync paradigm is already fully covered by the two units SyncAll (full barrier) + IBSet/IBWait (one-to-one)**, so this API is not given its own separate unit.
